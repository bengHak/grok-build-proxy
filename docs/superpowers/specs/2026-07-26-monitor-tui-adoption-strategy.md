## Adopted revisions (post-verify)

Verifier set `approved=false`. Treat these as hard constraints on the phased plan below:

1. **No global Active/Recent panes** (blocker on Phase 4). Density work stays inside session-centric widgets (tiered columns + per-session sparklines only).
2. **Phase 1 quit:** `Mode::ConfirmQuit` — `q` arms, `y` confirms, `n`/`Esc` cancels; while confirming, `y`/`Y` must not run `try_export`. Shared shutdown signal into axum `with_graceful_shutdown`; Ctrl-C skips confirm but still drains.
3. **Phase 2 contract:** extend `RequestEvent` only (no parallel bus); non-terminal observes mutate **active map only**; never push failures/recent on progress; throttle stream progress; prove Completed does not double-count.
4. **Phase 3 rates:** if header tok/s becomes generation-window, **relabel** vs fleet 1 Hz lifetime sparkline; update tests/README. Demo uses `Dashboard::observe` fixtures, not a CCP `MockMonitor` twin.
5. **Recent ring:** default ≥200 via `GROK_BUILD_PROXY_RECENT_CAP`, distinct from `GROK_BUILD_PROXY_FAILURE_CAP`.

## North star

Make the bonefish serve monitor a safe, live cockpit for multi-session Codex/Kimi traffic—truthful hang diagnosis and generation rates—without abandoning session-centric Failures/diagnostics or the widget-module TUI.

## Verifier revised summary

Bonefish already has a session-centric ratatui monitor (sessions | session detail | Failures, widgets/*), a single RequestEvent bus (Started/Completed/Failed), terminal latency diagnostics, wall-clock and fleet lifetime tok/s, failure-ring export, and env-tunable FAILURE_CAP—but immediate q-quit, no provider on monitor records, RECENT_CAP fixed at 50, no live phase/progress, and monitor exit that drops axum without a shared drain. Phase 1 should add confirm-quit with an export-safe ConfirmQuit mode, shared graceful shutdown, Provider threaded from TransformedRequest through RequestEvent/store/UI, and an env-tunable recent ring (default ≥200, separate from FAILURE_CAP). Phase 2 should extend RequestEvent (Updated/phase/progress) so only the active map mutates until Completed/Failed, with throttled stream counters and bonefish phase labels (no Compacting, no parallel bus). Phase 3 should add generation_started_at–based tok/s for detail (and header only if clearly relabeled vs the lifetime fleet sparkline) plus a Dashboard-fixture offline demo command. Phase 4 should improve medium-width ColumnSpec density and per-session sparklines only—never a global Active/Recent pane that clones CCP layout or duplicates session_detail. Success still means no regressions to Failures, export, cache metrics, or diagnostic fields, with cargo test and keybinding docs updated each phase.

## Ranked gaps (actionable)

### graceful-quit-confirm — Graceful shutdown confirm (q → y/n; Ctrl-C force) (P0, M, risk=med)

- **Upstream:** TUI: q requests graceful shutdown with y/n confirm; Ctrl-C force-quits. Monitor and HTTP server share orderly teardown.
- **Bonefish today:** q/Q and Ctrl-C all return immediately from monitor::run; main tokio::select! ends and cancels the server with no confirm (help: "q/Q / Ctrl-C stop proxy").
- **Why:** Accidental keypress kills the whole serve process under the TUI. Port confirm mode + signal a shutdown channel so axum graceful_shutdown drains; keep Ctrl-C as force. Highest UX footgun vs upstream.
- **Touch:** `src/monitor/app.rs`, `src/monitor/mod.rs`, `src/monitor/widgets/help.rs`, `src/monitor/widgets/footer.rs`, `src/main.rs`

### live-request-phases — Live request phase labels (prepare → upstream → streaming) (P1, L, risk=med)

- **Upstream:** RequestStatus lifecycle Started→ProviderSelected→(Compacting)→Upstream→Streaming→Completed|Failed; GenerationStarted opens generation window without a status.
- **Bonefish today:** RequestEventKind is only Started|Completed|Failed. Active turns show wall-clock elapsed + attempt; phase timings exist only as post-terminal RequestDiagnostics ms fields.
- **Why:** Port a slim bonefish-native status (e.g. Preparing/Auth/Upstream/Streaming) via mid-request observe updates—not Compacting (Claude-Code-only). Maps cleanly onto existing diagnostic phases and makes hung turns readable in the TUI.
- **Touch:** `src/events.rs`, `src/proxy.rs`, `src/store.rs`, `src/monitor/widgets/session_detail.rs`, `src/monitor/mod.rs`

### stream-progress-updates — Mid-stream progress and late usage updates (P1, M, risk=med)

- **Upstream:** StreamProgress/UsageUpdated mutate active requests; can late-update recent after terminal for usage/throughput.
- **Bonefish today:** Observer sees Started then terminal Completed/Failed only (StreamObserveGuard/observe_stream_end). Active requests have no live tokens/bytes/chunk counters; usage appears only at end.
- **Why:** Without progress events, live monitor cannot show streaming health or partial rates. Port throttled progress publishes from the SSE/body path into Dashboard active map (and optional late recent patch if usage arrives late).
- **Touch:** `src/events.rs`, `src/proxy.rs`, `src/store.rs`, `src/monitor/widgets/session_detail.rs`

### generation-window-throughput — Generation-window tok/s (not full request wall clock) (P1, M, risk=med)

- **Upstream:** Throughput prefers tok/s then B/s then ev/s over generation_duration; tokens = output − generation_initial_output_tokens.
- **Bonefish today:** Request::tokens_per_second uses full started→ended duration; Session lifetime rate uses sum(output)/sample_seconds over complete turns; fleet metrics are 1 Hz means of that lifetime rate.
- **Why:** Wall-clock rates undercount streaming (auth/TTFT inflate denominator). Mark generation start at first content/usage sample (or first_chunk), compute generation-relative rates for header/detail while keeping fleet 1 Hz sparklines as a separate signal.
- **Touch:** `src/store.rs`, `src/proxy.rs`, `src/events.rs`, `src/monitor/widgets/metrics.rs`, `src/monitor/widgets/session_detail.rs`, `src/monitor/widgets/header.rs`

### provider-label-codex-kimi — Provider label on requests/sessions (Codex vs Kimi) (P1, S, risk=low)

- **Upstream:** ProviderSelected + session/request provider/model/effort columns and filters across multi-provider routing.
- **Bonefish today:** TransformedRequest.provider exists in proxy, but RequestEvent/Request/Session carry only model/requested_model/mapped/lite/fast—no provider field; sessions panel shows model only.
- **Why:** Bonefish already routes Codex + Kimi; omitting provider forces model-name archaeology. Thread Provider through event/store/UI columns (not generic multi-cloud chrome).
- **Touch:** `src/events.rs`, `src/proxy.rs`, `src/store.rs`, `src/monitor/widgets/sessions.rs`, `src/monitor/widgets/session_detail.rs`, `src/monitor/widgets/failures.rs`, `src/report.rs`

### demo-mock-monitor — Deterministic demo/mock monitor CLI (P1, M, risk=low)

- **Upstream:** claude-code-proxy demo + MockMonitor tick simulation (250ms, multi-status/provider, bucket advancement) without bind/credentials.
- **Bonefish today:** No demo subcommand or mock store. TUI only via serve with real traffic; unit/render_test fixtures exist but no interactive dry-run path.
- **Why:** Unblocks UI iteration and screenshot/docs without auth. Implement a bonefish-shaped MockDashboard (Started/phase/fail kinds/retry_candidate/cache) behind `grok-build-proxy demo` rather than copying CCP fixtures/paths.
- **Touch:** `src/main.rs`, `src/monitor/mod.rs`, `src/store.rs`

### global-active-recent-tables — Global Active + Recent request tables (P2, L, risk=med)

- **Upstream:** Vertical panes: Sessions, Active, Recent, Events with focus on Sessions+Recent and Enter detail.
- **Bonefish today:** Sessions (active-only) + SessionDetail (per-session active then recent turns) + Failures. Snapshot has active/recent rings (recent cap 50) but no global Active/Recent panes.
- **Why:** Session-centric + failures is a deliberate bonefish strength; do not replace Failures. Optional global Recent (and compact Active strip) helps multi-session triage. Prefer additive panel or detail mode over cloning CCP layout wholesale.
- **Touch:** `src/monitor/mod.rs`, `src/monitor/app.rs`, `src/monitor/widgets/mod.rs`, `src/store.rs`

### session-token-bucket-sparklines — Per-session 10s output-token bucket sparklines (P2, M, risk=low)

- **Upstream:** session_output_buckets with SESSION_TOKEN_BUCKET_SECS=10 feeding session token sparklines.
- **Bonefish today:** Fleet metrics sparklines (tok/s 1 Hz, fail%, done, cache) only; sessions show scalar lifetime t/s, no time-bucket history per session.
- **Why:** Nice for spotting bursty sessions. Record 10s buckets on completion (and progress if added); render spark in session detail summary. Lower priority than generation-window rates.
- **Touch:** `src/store.rs`, `src/monitor/widgets/session_detail.rs`, `src/monitor/widgets/sessions.rs`

### layout-tier-columns — Multi-tier responsive column collapse (P2, M, risk=low)

- **Upstream:** LayoutTier Emergency→Wide + ColumnSpec fixed/flex widths so request tables drop/expand columns by terminal width.
- **Bonefish today:** Binary narrow/short (width<80 or height<28) single focused panel; metrics gated at ≥64×18. List rows use fixed truncate widths, not tiered column sets.
- **Why:** Bonefish already handles emergency layout. Intermediate tiers would keep more columns on medium terminals without full CCP table rewrite. Port ColumnSpec pattern for sessions/turns/failures rows only.
- **Touch:** `src/monitor/mod.rs`, `src/monitor/widgets/sessions.rs`, `src/monitor/widgets/session_detail.rs`, `src/monitor/widgets/failures.rs`

### recent-ring-capacity — Raise completed recent ring (50 → ~200) (P2, S, risk=low)

- **Upstream:** DEFAULT_RECENT_LIMIT=200 VecDeque of completed requests for history and session aggregation.
- **Bonefish today:** RECENT_CAP=50 for recent and errors; failure ring default 200 (GROK_BUILD_PROXY_FAILURE_CAP). Completed id set clears after 200.
- **Why:** Low-cost history depth for session turn lists and multi-session debugging. Prefer env-tunable recent cap mirroring failure cap rather than hard-coding CCP’s 200 only.
- **Touch:** `src/store.rs`, `README.md`

## Phased plan

### Phase 1: Phase 1 — Safety + identity

Eliminate accidental q-kills via confirm+graceful drain; surface Codex/Kimi provider; deepen recent history with an env-tunable ring.

- App confirm-quit mode (q→y/n); Ctrl-C force; update help.rs + footer.rs + README
- Shared shutdown signal: monitor quit + main axum with_graceful_shutdown drain (src/main.rs, monitor/mod.rs)
- Thread Provider from TransformedRequest through RequestEvent/Request/Session/FailureRecord (events.rs, proxy.rs, store.rs)
- Show compact codex/kimi on sessions, session_detail, failures, report columns
- Env-tunable recent/errors cap (default ~200); document GROK_BUILD_PROXY_RECENT_CAP in README
- Unit tests: confirm-mode keys; provider on Started; recent truncate at new cap

**Done when:** q never stops serve without y; Ctrl-C still force-exits; provider visible on list/detail/failures; recent default ≥200; tests green and help/README match.

### Phase 2: Phase 2 — Live turn lifecycle

Active turns show bonefish-native phase labels and throttled mid-stream progress so hung and slow streams are diagnosable live.

_Depends on:_ Phase 1 — Safety + identity

- Extend RequestEventKind (or Updated) for phase + progress; Dashboard mutates active only until terminal
- Proxy observe at prepare/auth/upstream/first-chunk boundaries mapped to Preparing/Auth/Upstream/Streaming (no Compacting)
- Throttled SSE/body StreamProgress into active map; optional late recent usage patch
- session_detail active rows: phase, wall elapsed, live counters; preserve terminal failure taxonomy
- Tests: re-observe phase transitions; progress does not double-count on Completed; StreamObserveGuard paths

**Done when:** Hung auth/upstream turns show non-terminal phase; streaming counters advance before Completed; Completed/Failed remain sole failure-ring terminals; tests green.

### Phase 3: Phase 3 — Generation rates + demo

Report generation-window tok/s for turn UX and ship a deterministic offline demo that reuses Dashboard::observe fixtures.

_Depends on:_ Phase 2 — Live turn lifecycle

- Mark generation_started_at (first content/usage or first_chunk); generation-relative tokens_per_second in store.rs
- header/session_detail use generation rates; keep fleet 1 Hz lifetime sparkline as separate metrics signal
- CLI grok-build-proxy demo: scripted observe sequence (phases, fail kinds, retry_candidate, cache) into monitor::run without bind/creds
- Prefer fixture helpers on Dashboard over a separate MockMonitor type tree
- Tests: TTFT-inflated wall rate vs higher generation rate; demo fixtures exercise Started→progress→terminal

**Done when:** Generation tok/s > wall-clock on TTFT-heavy turns; demo launches TUI offline; README documents demo; tests green.

### Phase 4: Phase 4 — Surface density

Improve medium-terminal density and multi-session triage additively without replacing Failures or cloning CCP layout.

_Depends on:_ Phase 3 — Generation rates + demo

- ColumnSpec-style tiered columns for sessions/turns/failures; keep narrow/short emergency single-focus layout
- Per-session 10s output-token buckets on completion (and progress if present); spark in session_detail only
- **Do not** add global Active/Recent panes (verifier blocker — duplicates session_detail, drifts to CCP layout)
- render tests at multiple widths; no new focus panes required
- No failure-export or diagnostics field regressions

**Done when:** Medium widths retain more columns; session sparklines render after traffic; Failures/export intact; tests green.

### bonefish-pipeline

Monitor pipeline: proxy emits RequestEvent (Started/Completed/Failed only) and session prompt/cwd via Observer; Dashboard aggregates into Snapshot (sessions, active/recent turns, failure ring cap 200, cache token totals, 1 Hz metrics); RequestDiagnostics tracks prepare/credential/headers/first_chunk phases plus fingerprint; retry_candidate marks same-session fingerprint matches within 30s with a suspicious terminal; --no-monitor or non-TTY disables observer and TUI.

Capabilities:
- RequestEventKind: Started|Completed|Failed only
- FailureKind: UpstreamHttp, UpstreamConnect, AuthRetryFailed, StreamIo, StreamTerminalFailed, ProxyAssemble, ClientRejected, Unknown
- RequestDiagnostics phases: proxy_prepare_ms, credential_ms, upstream_headers_ms, first_chunk_ms + body/items/fingerprint
- Session last_prompt and cwd via observe_session_context
- TokenUsage cache accounting: cached_input_tokens, cache_write_tokens, fresh_input_tokens, cache_read_ratio
- Failure ring default 200 (GROK_BUILD_PROXY_FAILURE_CAP); recent/errors cap 50
- retry_candidate: same session+fingerprint within 30s and suspicious terminal
- Auth retry re-emits Started with attempt=2
- --no-monitor or non-interactive: observer None, plain stderr logs
- Report export omits error messages, prompts, and bodies
